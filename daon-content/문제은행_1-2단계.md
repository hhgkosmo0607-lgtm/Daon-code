## 1-1. 뭘 만들지 정하기

**Q1** (choice)
> 아래는 실제로 AI에게 "일기 앱 만들어줘"라고만 요청해서 받은 결과입니다. 원하던 건 "날짜별로 과거 일기를 찾아보는" 기능이었습니다. 문제가 생긴 가장 직접적인 원인은?
> ```
> [만들어진 화면]
> - 제목 입력창 / 내용 입력창 / 저장 버튼
> ```
- ① AI 성능이 낮아서
- ② 요청에 "과거 기록 조회"에 대한 언급이 아예 없어서, AI가 만들 근거가 없었다 ✓
- ③ 저장 버튼을 안 만들어줘서
- ④ 입력창 개수가 부족해서

**해설**: AI는 요청에 없는 건 만들지 않아요. 만들 근거가 없으니까요. 먼저 "무엇을 만들지"를 한 문장으로 정리해두면, 빠진 기능을 미리 알아챌 수 있어요.

**Q2** (choice)
> "운동 기록 앱을 만들건데, 오늘 한 운동 종류랑 시간을 적을 수 있게 해줘" — 이 문장에서 **목적**에 해당하는 부분은?
- ① 운동 기록 앱을 만들건데 ✓
- ② 오늘 한
- ③ 운동 종류랑 시간을
- ④ 적을 수 있게 해줘

**해설**: "무엇을 만들려는지"가 목적이에요. 이게 먼저 나와야 AI가 전체 그림을 잡고, 그 다음 세부 기능을 채울 수 있어요.

**Q3** (choice)
> 아이디어를 한 문장으로 정리할 때, 꼭 들어가야 할 것은?
- ① 누가 / 무엇을 위해 / 무엇을 하는 앱인지 ✓
- ② 사용할 프로그래밍 언어
- ③ 예상 개발 기간
- ④ 앱 이름

**해설**: 기술 선택은 AI가 알아서 해요. 비개발자가 정해야 할 건 "누구를 위한, 무엇을 하는 앱인가"입니다.

**Q4** (blank)

> ```
- ① 혼자 공부하는 사람 / 공부 시간을 기록 ✓

- ③ 사람들 / 편리하게
- ④ 나 / 잘되는

**해설**: 대상과 핵심 동작이 구체적일수록 AI가 상상으로 채울 여지가 줄어들어요.

**Q5** (choice)
> "쇼핑몰 만들어줘"라고만 요청했을 때 가장 흔히 생기는 문제는?
- ① AI가 아예 대답을 안 한다
- ② 만들어진 결과가 생각과 다른데, 어디가 왜 다른지 설명하기 어렵다 ✓
- ③ 앱이 실행되지 않는다
- ④ 비용이 더 든다

**해설**: 막연한 요청은 막연한 결과로 돌아와요. 기준이 없으니 수정 요청도 애매해지는 악순환이 생깁니다.

**Q6** (choice)

- ③ 어떤 데이터베이스를 쓸지 ✓
- ④ 어떤 화면이 필요한지

**해설**: 기술 스택 선택은 AI가 상황에 맞게 해줘요. 지금은 "무엇을"에만 집중하면 됩니다.

**Q7** (compare)

## 1-2. 화면부터 그려보기

> ```

- ③ 글자 색이 마음에 안 든다

**해설**: "당연히 있어야 하는데 빠진 것"은 미리 그려봤으면 알아챘을 문제예요.

- ② 그림은 버리고 말로만 설명한다
- ③ 그림을 다른 사람에게 보여준다

- ① 숫자 표시도 AI가 알아서 추가해준다
- ② 장바구니 아이콘만 만들어지고, 개수 표시는 따로 요청하기 전까진 없을 가능성이 높다 ✓
- ③ 에러가 난다
- ④ 장바구니 기능 자체가 안 만들어진다

**해설**: 그림에 없는 디테일은 요청에도 빠지기 쉬워요. "당연히 있겠지" 싶은 것일수록 그려서 확인해야 해요.

**Q7** (order)

**해설**: 무엇을 만들지 → 어떻게 보일지 → 그걸 전달하기 순서로 가면 AI가 상상으로 채울 여지가 크게 줄어요.

## 1-3. AI에게 처음 요청하기

> ```
> 요청 A: "앱 만들어줘"
>   → 결과: 정체불명의 "샘플 할일 앱"이 생성됨
>
> 요청 B: "강아지 산책 기록 앱을 만들어줘.

> ```
- ① AI가 그날따라 컨디션이 안 좋아서
- ② "무엇을 만들지"에 대한 정보가 없어서, AI가 흔한 예시로 채워 넣은 것 ✓
- ③ 요청이 너무 짧아서 시스템 오류가 난 것
- ④ "앱"이라는 단어가 금지어라서

**해설**: 정보가 없으면 AI는 가장 흔한 패턴으로 빈칸을 채워요. 그 상상이 내 생각과 맞을 확률은 낮습니다.

**Q3** (choice)

**Q5** (choice)

## 1-4. 받은 화면들이 뭔가

**Q1** (choice)
> Cursor를 열었더니 이런 화면 배치가 보입니다. "명령어를 입력해서 실행시키는 곳"은?
> ```
> 왼쪽: 폴더 목록 (src, components, App.jsx...)
> 가운데: App.jsx 내용이 텍스트로 표시됨
> 하단: 검은 바탕에 $ 표시가 있는 좁은 창
> ```
- ① 왼쪽 폴더 목록
- ② 가운데 텍스트 영역
- ③ 하단의 $ 표시가 있는 창 ✓
- ④ 셋 다 같은 역할

**해설**: `$` 프롬프트가 보이는 하단 영역이 터미널이에요. 왼쪽은 파일 탐색, 가운데는 코드 편집 영역입니다.

**Q2** (choice)
> 에디터(Cursor, VS Code)는 무엇을 하는 곳일까요?
- ① 완성된 앱을 실행해서 보는 곳
- ② 코드를 쓰고 읽는 곳 ✓
- ③ 인터넷에 연결하는 곳
- ④ 파일을 삭제하는 곳

**해설**: 워드프로그램과 비슷해요. 코드라는 특수한 글을 쓰고 읽는 곳이지, 그 자체로 앱이 실행되는 건 아니에요.

**Q3** (choice)
> 완성된 화면을 실제로 눈으로 보는 곳은?
- ① 에디터
- ② 터미널
- ③ 브라우저 (크롬, 사파리 등) ✓
- ④ 셋 다 아님

**해설**: 평소 인터넷 볼 때 쓰는 그 프로그램이 맞아요. `localhost:5173` 같은 주소를 여기 입력해서 결과를 확인합니다.

**Q4** (order)
> 코드를 고쳐서 화면에 반영되기까지의 순서는?
- 에디터에서 코드 확인/수정
- 터미널에서 실행 명령 입력
- 브라우저에서 결과 확인

**정답 순서**: 1 → 2 → 3

**해설**: 이 셋이 한 세트로 움직여요. 에디터에서 손보고, 터미널에서 실행하고, 브라우저에서 확인합니다.

**Q5** (choice)
> 코드를 고쳤는데 브라우저 화면이 그대로입니다. 가장 먼저 확인할 것은?
- ① 브라우저를 새로고침했는지 ✓
- ② 컴퓨터를 재부팅했는지
- ③ 인터넷이 끊겼는지
- ④ 에디터를 재설치했는지

**해설**: 대부분 자동 반영되지만 가끔 새로고침이 필요해요. 가장 간단하고 흔한 원인부터 확인하는 습관이 중요합니다.

**Q6** (choice)
> AI가 "터미널에서 이 명령어를 실행하세요"라고 안내했습니다. 어디에 입력해야 할까요?
- ① 브라우저 주소창
- ② 에디터의 코드 작성 영역
- ③ 검은 화면의 터미널 창 ✓
- ④ 아무 데나 상관없다

**해설**: 다른 곳에 입력하면 아무 일도 안 일어나거나 엉뚱한 결과가 나와요.

**Q7** (choice)
> 셋의 관계를 가장 잘 설명한 것은?
- ① 셋 중 하나만 있으면 충분하다
- ② 에디터는 요리하는 곳, 터미널은 불을 켜는 곳, 브라우저는 완성된 요리를 먹는 곳 ✓
- ③ 브라우저가 나머지 둘을 대체한다
- ④ 순서는 상관없이 아무거나 먼저 써도 된다

**해설**: 코드(재료)를 에디터에서 준비하고, 터미널(불)로 실행시키고, 브라우저(접시)로 결과를 확인합니다.

## 1-5. npm run dev, 이 세 단어

**Q1** (choice)
> 터미널에 `npm run dev`를 입력하고 엔터를 눌렀습니다. 무슨 일이 일어날까요?
- ① 파일이 전부 삭제된다
- ② 내 컴퓨터 안에서 앱이 실행되어, 브라우저로 볼 수 있게 된다 ✓
- ③ 인터넷에 앱이 공개된다
- ④ 코드가 자동으로 고쳐진다

**해설**: "지금까지 만든 코드를 실행해서 미리보기 해줘"라는 명령이에요. `dev`는 개발(development)의 줄임말입니다.

**Q2** (choice)
> `npm install`과 `npm run dev`의 차이는?
- ① 둘 다 똑같다
- ② install은 필요한 재료를 받는 것, dev는 그 재료로 실행하는 것 ✓
- ③ install은 삭제, dev는 설치
- ④ dev를 먼저 하고 install은 나중에 한다

**해설**: `install`은 라이브러리를 받아오는 과정(보통 맨 처음 한 번)이고, `dev`는 그걸 바탕으로 화면을 켜는 과정이에요.

**Q3** (choice)
> `npm run dev`를 실행했더니 이렇게 떴습니다. 다음에 뭘 해야 할까요?
> ```
> VITE ready in 320ms
> ➜ Local: http://localhost:5173
> ```
- ① 저 주소를 브라우저 주소창에 입력해서 들어가본다 ✓
- ② 터미널을 바로 끈다
- ③ 컴퓨터를 재부팅한다
- ④ 아무것도 안 해도 자동으로 화면이 뜬다

**해설**: `Local:` 뒤의 주소가 "여기로 들어오면 결과가 보여요"라는 안내예요.

**Q4** (blank)
> 실행 중인 서버를 멈추려면 터미널에서 무엇을 눌러야 할까요?
> ```
> 터미널 창에서 ___ 를 누른다
> ```
- ① Ctrl + C (Mac은 Command + C) ✓
- ② Enter
- ③ Esc
- ④ Delete

**해설**: `Ctrl + C`가 "지금 실행 중인 걸 멈춰줘"라는 명령이에요. 창만 닫으면 뒤에서 계속 돌고 있을 수도 있어요.

**Q5** (choice)
> 서버를 안 끄고 새 터미널에서 또 실행했더니 이런 에러가 났습니다. 원인은?
> ```
> Error: listen EADDRINUSE :::5173
> ```
- ① 이전 서버가 이미 그 자리(포트)를 쓰고 있어서 ✓
- ② 인터넷이 끊겨서
- ③ 코드에 오타가 있어서
- ④ 파일이 삭제돼서

**해설**: 같은 번호(포트)로 두 개를 동시에 못 켜요. 이전 터미널에서 `Ctrl+C`로 먼저 꺼야 합니다.

**Q6** (choice)
> `npm install`을 생략하고 바로 `npm run dev`만 했더니 이런 에러가 났습니다. 관계는?
> ```
> Error: Cannot find module 'react'
> ```
- ① 무관하다, 우연이다
- ② `install`로 받아야 할 react 라이브러리가 없는 상태에서 실행하려 해서 ✓
- ③ dev 명령어 자체가 잘못됐다
- ④ 인터넷 연결 문제다

**해설**: "필요한 재료가 없으면 실행할 수 없다"는 게 이 에러 메시지로 나타난 거예요.

**Q7** (choice)
> 새로 받은 프로젝트를 처음 실행할 때 올바른 순서는?
- ① `npm run dev` → `npm install`
- ② `npm install` → `npm run dev` ✓
- ③ `npm run dev`만 하면 된다
- ④ 순서 상관없이 여러 번 반복

**해설**: 처음엔 반드시 `install`로 재료를 받고, 그다음 `dev`로 실행해요. 이후 코드만 고칠 땐 `dev`만 켜두면 됩니다.

# 2단계. 받은 코드, 뭐가 뭔지

## 2-1. 파일이 왜 여러 개인가

**Q1** (choice)
> AI가 만들어준 프로젝트에 파일이 10개 넘게 있습니다. 왜 한 파일에 다 안 넣었을까요?
- ① 랜덤으로 나뉜 것뿐이다
- ② 화면을 조각(버튼, 목록, 헤더 등)으로 나눠서 각자 따로 관리하려고 ✓
- ③ 파일이 많을수록 앱이 빨라져서
- ④ AI가 실수로 여러 개 만든 것이다

**해설**: 레고 블록처럼 화면을 작은 조각으로 나눠두면, 하나만 고칠 때 그 조각만 보면 돼요. 이 조각을 **컴포넌트**라고 불러요.

**Q2** (choice)
> 아래 파일 목록에서 "버튼 하나"를 담당하는 파일은?
> ```
> components/
>   Header.jsx
>   Button.jsx
>   ProductList.jsx
> App.jsx
> ```
- ① Header.jsx
- ② Button.jsx ✓
- ③ ProductList.jsx
- ④ App.jsx

**해설**: 파일 이름이 대부분 그 조각의 역할을 나타내요.

**Q3** (choice)
> `App.jsx`처럼 이름이 특별한 파일은 보통 어떤 역할일까요?
- ① 제일 안 중요한 파일
- ② 다른 조각들을 모아서 전체 화면을 완성하는 파일 ✓
- ③ 에러 메시지를 저장하는 파일
- ④ 이미지 파일

**해설**: 레고 조립 설명서 같은 역할이에요. "헤더 넣고, 그 아래 상품목록 넣고..." 식으로 조각들을 배치합니다.

**Q4** (blank)
> 컴포넌트를 한 문장으로 설명하면?
> ```
> 컴포넌트는 화면의 ___ 단위다
> ```
- ① 조각 ✓
- ② 색깔
- ③ 속도
- ④ 파일 크기

**해설**: 버튼 하나, 카드 하나, 헤더 하나가 각각 컴포넌트가 될 수 있어요.

**Q5** (choice)
> "로그인 버튼 색깔만 바꿔줘"라고 했는데 다른 버튼 색까지 바뀌었습니다. 원인은?
- ① AI가 고장났다
- ② 여러 버튼이 같은 컴포넌트(공용 Button.jsx)를 함께 쓰고 있어서 ✓
- ③ 인터넷이 느려서
- ④ 색깔은 원래 랜덤이다

**해설**: 공용 부품을 고치면 그 부품을 쓰는 모든 곳이 함께 바뀌어요. "로그인 버튼에서만 쓰는 새 버튼을 만들어줘"라고 요청하면 피할 수 있어요.

**Q6** (choice)
> 파일 이름이 `UserProfileCard.jsx`입니다. 짐작할 수 있는 역할은?
- ① 사용자 프로필을 카드 형태로 보여주는 조각 ✓
- ② 사용자 목록 전체를 지우는 기능
- ③ 로그인 처리 로직
- ④ 서버 주소 설정

**해설**: Card, List, Button, Form 같은 단어가 붙으면 그게 힌트가 돼요.

**Q7** (compare)
> 새 기능(찜하기 버튼)을 추가할 때 더 좋은 요청은?
>
> **A** `"찜하기 기능 추가해줘"`
> **B** `"찜하기 버튼을 새 컴포넌트로 만들어서 상품카드 안에 넣어줘"`
- ① A
- ② B ✓

**해설**: 컴포넌트 단위로 요청하면 AI도 어디에 뭘 만들지 명확히 알아들어요.

## 2-2. 값을 담는 상자

**Q1** (choice)
> 아래 코드는 무엇을 하고 있을까요?
> ```js
> const name = "홍길동"
> ```
- ① `name`이라는 이름으로 "홍길동"을 저장한다 ✓
- ② "홍길동"이라는 이름의 함수를 만든다
- ③ 화면에 "홍길동"을 출력한다
- ④ "홍길동"이 맞는지 확인한다

**해설**: `const 이름 = 값`은 값에 이름표를 붙여두는 것입니다. `=`는 "같다"가 아니라 "넣는다"는 뜻이에요.

**Q2** (choice)
> AI가 만들어준 코드입니다. 값을 저장하는 줄은 몇 번일까요?
> ```js
> 1  function Welcome() {
> 2    const message = "환영합니다"
> 3    return <h1>{message}</h1>
> 4  }
> ```
- ① 1번
- ② 2번 ✓
- ③ 3번
- ④ 4번

**해설**: 2번에서 저장하고, 3번에서 그 값을 화면에 꺼내 쓰고 있어요.

**Q3** (choice)
> 아래 중 나중에 값을 바꿀 수 있는 것은?
> ```js
> const price = 1000
> let count = 1
> ```
- ① `price`
- ② `count` ✓
- ③ 둘 다 가능
- ④ 둘 다 불가능

**해설**: `const`는 한 번 정하면 못 바꾸고, `let`은 바꿀 수 있어요. AI는 대부분 `const`를 씁니다.

**Q4** (blank)
> 장바구니 개수는 계속 바뀝니다. 빈칸에 알맞은 것은?
> ```js
> ___ cartCount = 0
> ```
- ① `let` ✓
- ② `const`
- ③ `function`
- ④ `return`

**해설**: 값이 바뀌어야 하니까 `let`입니다. `const`를 쓰면 나중에 개수를 늘릴 때 에러가 나요.

**Q5** (choice)
> 이 코드를 실행하면 어떻게 될까요?
> ```js
> const total = 5000
> total = 6000
> ```
- ① 6000으로 바뀐다
- ② 에러가 난다 ✓
- ③ 5000 그대로다
- ④ 11000이 된다

**해설**: `Assignment to constant variable` 에러가 나요. 이 에러를 보면 `const`를 `let`으로 바꿔달라고 요청하면 됩니다.

**Q6** (choice)
> 아래 코드에서 `isLoading`에 들어있는 값은?
> ```js
> const isLoading = true
> ```
- ① 문자 "true"
- ② 참/거짓 값 `true` ✓
- ③ 숫자 1
- ④ 비어있음

**해설**: 따옴표가 없으면 진짜 참/거짓 값이에요. `is~`로 시작하는 이름은 대부분 참/거짓을 담는다는 신호입니다.

**Q7** (compare)
> 사용자 이름을 저장하려고 합니다. 더 적절한 코드는?
>
> **A** `const a = "김철수"`
> **B** `const userName = "김철수"`
- ① A
- ② B ✓

**해설**: 나중에 코드를 다시 볼 때 뭘 담은 건지 바로 알 수 있으니까요.

## 2-3. 값의 종류

**Q1** (choice)
> 아래 세 줄에서 "숫자"로 저장된 것은?
> ```js
> const age = 25
> const ageText = "25"
> const isAdult = true
> ```
- ① `age` ✓
- ② `ageText`
- ③ `isAdult`
- ④ 셋 다 숫자다

**해설**: 따옴표가 없는 `25`는 진짜 숫자예요. `"25"`는 겉보기엔 같아도 사실은 글자(문자열)입니다.

**Q2** (choice)
> 아래 중 문자열은?
> ```js
> const price = 3000
> const category = "전자제품"
> const inStock = false
> ```
- ① `price`
- ② `category` ✓
- ③ `inStock`
- ④ 없음

**해설**: 따옴표로 감싸져 있으면 문자열이에요. 사람이 읽는 텍스트라고 생각하면 됩니다.

**Q3** (choice)
> 숫자와 숫자처럼 생긴 문자열을 더하면?
> ```js
> const a = 5 + 5        // 숫자 + 숫자
> const b = "5" + "5"    // 문자열 + 문자열
> ```
- ① a는 10, b는 10
- ② a는 10, b는 "55" ✓
- ③ a도 b도 "55"
- ④ 둘 다 에러가 난다

**해설**: 문자열끼리 `+`는 이어붙이기예요. 따옴표 유무가 실제 동작을 완전히 바꿉니다.

**Q4** (blank)
> 이 값에는 어떤 종류가 들어가야 할까요?
> ```js
> const isLoggedIn = ___
> ```
- ① `true` ✓
- ② `"true"`
- ③ `1`
- ④ `"로그인됨"`

**해설**: 예/아니오로 답할 수 있는 값은 참/거짓으로 저장해요. `"true"`는 그냥 글자일 뿐입니다.

**Q5** (choice)
> 가격 계산을 하려는데 이런 결과가 나왔습니다. 원인은?
> ```
> 5 + "5"  결과: "55"
> ```
- ① 가격을 숫자가 아니라 문자열로 받아와서 더했을 가능성 ✓
- ② 인터넷 문제
- ③ AI가 계산을 못해서
- ④ 원래 이렇게 나오는 게 맞다

**해설**: 서버나 입력창에서 받아온 값이 숫자처럼 보여도 실제로는 문자열인 경우가 흔해요.

**Q6** (choice)
> `null`이라는 값은 어떤 의미로 읽어야 할까요?
- ① 숫자 0
- ② 의도적으로 "아직 값이 없음"을 나타내는 표시 ✓
- ③ 에러 메시지
- ④ 빈 문자열

**해설**: 로그인 전에는 `user = null`로 뒀다가, 로그인하면 실제 정보로 바뀌는 식으로 쓰여요.

**Q7** (compare)
> 전화번호를 저장하려 합니다. 더 적절한 코드는?
>
> **A** `const phone = 01012345678`
> **B** `const phone = "010-1234-5678"`
- ① A
- ② B ✓

**해설**: 전화번호는 계산할 일이 없고, 하이픈이나 맨 앞 0을 그대로 표시해야 해서 문자열이 맞아요.

## 2-4. 목록과 뭉치

**Q1** (choice)
> 아래 코드는 무엇을 담고 있을까요?
> ```js
> const fruits = ["사과", "바나나", "포도"]
> ```
- ① 과일 이름 여러 개를 순서대로 담은 목록 ✓
- ② 과일 하나에 대한 자세한 정보
- ③ 함수
- ④ 참/거짓 값

**해설**: 대괄호 `[]`는 여러 개를 순서대로 나열한 **배열**이에요.

**Q2** (choice)
> 아래에서 "한 사람에 대한 여러 정보를 묶어둔" 부분은?
> ```js
> const user = { name: "김철수", age: 25 }
> ```
- ① `user` 전체 ✓
- ② `name`만
- ③ `age`만
- ④ `25`만

**해설**: 중괄호 `{}`는 관련된 정보들을 이름표와 함께 묶어둔 **객체**예요.

**Q3** (choice)
> 배열과 객체의 차이를 가장 잘 설명한 것은?
- ① 배열은 순서 있는 목록, 객체는 이름표 붙은 정보 뭉치 ✓
- ② 둘은 완전히 같다
- ③ 배열은 숫자만, 객체는 글자만 담을 수 있다
- ④ 객체가 배열보다 항상 크다

**해설**: 상품 여러 개는 배열, 상품 하나의 이름·가격·재고는 객체예요.

**Q4** (choice)
> 사용자 이름을 꺼내려면?
> ```js
> const user = { name: "김철수", age: 25 }
> ```
- ① `user[0]`
- ② `user.name` ✓
- ③ `user.age`
- ④ `user["0"]`

**해설**: 객체에서 값을 꺼낼 땐 이름표를 점(`.`)으로 붙여서 써요.

**Q5** (choice)
> 이 코드에서 문제가 생기는 이유는?
> ```js
> const fruits = ["사과", "바나나"]
> console.log(fruits.name)
> ```
- ① 배열에는 `.name`이라는 이름표가 없어서 undefined가 나옴 ✓
- ② 과일 이름이 틀려서
- ③ 배열은 원래 못 쓴다
- ④ console.log가 잘못됐다

**해설**: 배열은 순서(번호)로 꺼내야 해요(`fruits[0]`).

**Q6** (choice)
> 아래 코드는 무엇을 나타낼까요?
> ```js
> const products = [
>   { name: "티셔츠", price: 20000 },
>   { name: "청바지", price: 45000 }
> ]
> ```
- ① 상품 여러 개(배열)를, 각각 이름과 가격 정보(객체)로 담은 것 ✓
- ② 상품 하나에 대한 정보
- ③ 에러 메시지 목록
- ④ 함수 목록

**해설**: "배열 안에 객체가 여러 개" 구조로, 상품 목록·댓글 목록에 흔히 쓰여요.

**Q7** (compare)
> 학생 3명의 이름과 점수를 저장하려 합니다. 더 적절한 구조는?
>
> **A**
> ```js
> const students = ["김철수", 90, "이영희", 85]
> ```
> **B**
> ```js
> const students = [
>   { name: "김철수", score: 90 },
>   { name: "이영희", score: 85 }
> ]
> ```
- ① A
- ② B ✓

**해설**: A는 이름과 점수가 뒤섞여 어떤 게 누구 것인지 헷갈려요. B처럼 객체로 묶으면 명확합니다.

## 2-5. 이 코드는 왜 반복되나

**Q1** (choice)
> 아래 코드는 무엇을 하고 있을까요?
> ```js
> const fruits = ["사과", "바나나", "포도"]
> fruits.map(fruit => <li>{fruit}</li>)
> ```
- ① 배열에 있는 각 항목마다 화면에 보여줄 요소를 하나씩 만든다 ✓
- ② 배열을 지운다
- ③ 배열 순서를 뒤집는다
- ④ 배열에서 하나만 뽑는다

**해설**: `map()`은 목록을 하나씩 돌면서 각각을 다른 모양으로 바꿔주는 역할이에요.

**Q2** (choice)
> 아래 코드에서 "반복"이 일어나는 줄은?
> ```jsx
> 1  function FruitList() {
> 2    const fruits = ["사과", "바나나"]
> 3    return (
> 4      <ul>
> 5        {fruits.map(f => <li>{f}</li>)}
> 6      </ul>
> 7    )
> 8  }
> ```
- ① 2번
- ② 5번 ✓
- ③ 4번
- ④ 7번

**해설**: 과일이 2개면 `<li>`도 2개 생겨요.

**Q3** (choice)
> `map()`을 쓰지 않고 항목이 100개인 목록을 보여주려면?
- ① `<li>`를 100번 직접 써야 한다 ✓
- ② 자동으로 알아서 나온다
- ③ 불가능하다
- ④ 10개까지만 가능하다

**해설**: 데이터가 몇 개든 자동으로 화면에 반영되게 해주는 게 `map()`의 역할이에요.

**Q4** (blank)
> 상품 목록을 반복해서 보여주려면?
> ```jsx
> {products.___(p => <ProductCard product={p} />)}
> ```
- ① `map` ✓
- ② `delete`
- ③ `find`
- ④ `sort`

**해설**: "목록의 각 항목마다 화면 조각을 하나씩 만들어줘"라는 의도이므로 `map`이 맞아요.

**Q5** (choice)
> 콘솔에 이런 경고가 떴습니다. 무슨 뜻일까요?
> ```
> Warning: Each child in a list should have a unique "key" prop.
> ```
- ① 목록 항목마다 구분할 이름표(key)를 안 달아줘서 나는 경고 ✓
- ② 데이터가 하나도 없다는 뜻
- ③ 인터넷 연결 문제
- ④ 무시해도 되는 광고성 메시지

**해설**: 보통 `key={item.id}`처럼 고유값을 넣어주면 해결돼요. AI에게 "key 경고가 뜨는데 고쳐줘"라고 하면 됩니다.

**Q6** (choice)
> 아래 코드에서 `p`는 무엇을 가리킬까요?
> ```js
> products.map(p => <li>{p.name}</li>)
> ```
- ① products 배열 안의 항목 하나하나 (한 상품) ✓
- ② products 배열 전체
- ③ 화면 전체
- ④ 아무 의미 없는 글자

**해설**: "지금 돌고 있는 그 항목 하나"를 임시로 부르는 이름이에요. 다른 이름이어도 상관없습니다.

**Q7** (compare)
> 댓글 목록을 전부 보여주는 더 적절한 코드는?
>
> **A** `<div>{comments[0]}</div>`
> **B** `{comments.map(c => <div key={c.id}>{c.content}</div>)}`
- ① A
- ② B ✓

**해설**: A는 첫 번째 댓글 하나만 보여줘요. 전부 보여주려면 `map()`이 필요합니다.

## 2-6. 이 값은 어디서 왔나

**Q1** (choice)
> 아래 코드에서 `name="김철수"`는 무엇을 하는 걸까요?
> ```jsx
> <UserCard name="김철수" />
> ```
- ① `UserCard`에게 "이름은 김철수야"라고 값을 건네준다 ✓
- ② UserCard의 이름을 바꾼다
- ③ 아무 의미 없다
- ④ 에러를 발생시킨다

**해설**: 이렇게 건네주는 값을 **props**라고 불러요. "부모가 자식에게 재료를 건네준다"고 생각하면 됩니다.

**Q2** (choice)
> `UserCard`가 받는 값은 몇 개일까요?
> ```jsx
> <UserCard name="김철수" age={25} />
> ```
- ① 0개
- ② 1개
- ③ 2개 ✓
- ④ 3개

**해설**: `name`과 `age` 두 개를 건네주고 있어요.

**Q3** (choice)
> 아래에서 전달받은 이름을 쓰는 부분은?
> ```jsx
> function UserCard(props) {
>   return <p>이름: {props.name}</p>
> }
> ```
- ① `function UserCard(props)`
- ② `<p>이름: {props.name}</p>` ✓
- ③ `return`
- ④ 없음

**해설**: `props.name`으로 부모가 건네준 값을 꺼내 쓰고 있어요.

**Q4** (blank)
> 상품카드에 가격을 전달하려면?
> ```jsx
> <ProductCard ___={15000} />
> ```
- ① `price` ✓
- ② `15000`
- ③ `card`
- ④ `product`

**해설**: `이름={값}` 형태로 쓰고, 그 값이 뭔지 알아볼 수 있는 이름을 붙여요.

**Q5** (choice)
> 화면에 상품 이름이 안 뜨고 비어 있습니다. 원인은?
> ```jsx
> // 부르는 쪽
> <ProductCard title="티셔츠" />
>
> // 받는 쪽
> function ProductCard(props) {
>   return <p>{props.name}</p>
> }
> ```
- ① 넘길 땐 `title`로 보냈는데, 받을 땐 `props.name`으로 다른 이름을 찾고 있어서 ✓
- ② 상품이 실제로 없어서
- ③ 인터넷 문제
- ④ 컴포넌트 이름이 틀려서

**해설**: 넘기는 이름과 받는 이름이 정확히 일치해야 해요.

**Q6** (choice)
> 아래에서 "부모"와 "자식" 관계는?
> ```jsx
> function App() {
>   return <Header title="내 쇼핑몰" />
> }
> ```
- ① App이 부모, Header가 자식 ✓
- ② Header가 부모, App이 자식
- ③ 둘 다 부모
- ④ 관계 없음

**해설**: 값을 건네주는 쪽이 부모, 받는 쪽이 자식이에요.

**Q7** (compare)
> 같은 카드로 여러 상품을 보여주려 합니다. 더 적절한 코드는?
>
> **A**
> ```jsx
> <ProductCard />
> <ProductCard />
> ```
> **B**
> ```jsx
> <ProductCard name="티셔츠" price={20000} />
> <ProductCard name="청바지" price={45000} />
> ```
- ① A
- ② B ✓

**해설**: A는 어떤 상품인지 알려주는 값이 없어서 똑같은 빈 카드만 나와요.
