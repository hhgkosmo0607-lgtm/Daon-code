## 핵심 결정 요약

한눈에 보는 확정 사항입니다. 자세한 근거는 기획서를 참고하세요.

### 제품

```
타깃      바이브코딩으로 뭔가 만들지만 코드는 모르는 사람
컨셉      문법을 외워 "직접 짜기"가 아니라, AI가 준 코드를 "이해하기"
커리큘럼   지식 분류 순서가 아닌, 프로젝트 실제 여정 순서 (12단계 58레슨, 9~12단계는 확장 추가)
문맥      JavaScript + React (주요 바이브코딩 툴이 생성하는 스택)
```

### 기술

```
앱        React Native + Expo
백엔드     Supabase (유저 데이터만)
콘텐츠     로컬 JSON — Supabase에 콘텐츠 테이블 두지 않음
채점      Edge Function이 서버에서 확정, 클라이언트 계산은 신뢰하지 않음
보안      RLS로 progress/daily_xp/XP 컬럼 클라이언트 쓰기 차단
갱신      EAS Update로 스토어 심사 없이 콘텐츠 반영
```

### 게임화

```
XP        레슨 완료 10 + 만점 보너스 5 + 하루목표 20
          재도전은 0 (XP 파밍 방지)
          하루목표 보너스는 그날 1회만
게스트     정상 XP의 80%, 로그인 시 차액을 보너스로 환급
스트릭     Asia/Seoul 고정, 프리즈 7일마다 1개 (무료)
로그인     배치고사 본 사람 → 결과 확인 시점에 강제
          안 본 사람 → 1단계(5레슨) 완료 시점에 강제
```

### 지금 앱의 실제 상태

`submit-answer`(레슨 채점/XP/진도)와 `complete-placement`(배치고사 채점/레슨 건너뛰기)
두 Edge Function을 작성했습니다. 문제은행 원본 280문제 + 커리큘럼 확장(9~12단계) 126문제,
총 406문제를 전부 `content/questions/*.json`으로 변환해서 58레슨 전체가 콘텐츠상으로는
완성됐고, 온보딩 위저드(목적/자가진단/하루목표/알림시간/배치고사) + 로그인 게이트 + 게스트
안내 배너까지 만들었습니다. "문제가 너무 상식적"이라는 피드백에 따라 오답 선택지도 전면
재작성해서(그럴듯하지만 틀린 개념으로) 실제 이해 없이 소거법으로 풀리지 않게 했습니다.

Supabase 프로젝트(`daon-code`, ap-northeast-2)에 실제로 연결·배포하고, curl로 진짜
익명 세션을 만들어서 두 Edge Function의 채점·XP·RLS 차단·배치고사 로직까지 전부
검증했습니다. 남은 건 실제 Expo 앱을 켜서 화면(온보딩 UI, 배너 등)을 눈으로 확인하는
것뿐입니다 — 이건 사용자가 직접 해야 하는 부분입니다.

**온보딩에서 아직 안 한 것**:
- 구글/카카오 로그인 버튼 (Phase 3 마무리 항목)
- "게스트로 놓친 XP 돌려받기" 실제 금액 표시 (`calculatePendingBonus`는 있는데 화면에 미연결)
- 알림 실제 발송 (`notify_time` 저장까지만, 발송 스케줄러는 Phase 6)

### 2. Phase 7 — 콘텐츠 채우기 (완료, 확장까지 포함)

문제은행 3개 파일의 280문제를 `content/questions/*.json`으로 전부 변환했고, 이후
"너무 적고 상식적"이라는 피드백으로 9~12단계(18레슨, 126문제)를 새로 추가했습니다.
`content/lessons.json`도 12단계 58레슨 메타데이터 전체를 담고 있습니다.

**변환하면서 처리한 것**: 기존 `1-2.json`의 `order` 문제가 보기를 정답 순서 그대로
배열해놔서 탭 UI에 셔플 로직이 없다 보니 항상 자명하게 풀리는 버그가 있었는데, 보기
순서를 섞고 정답 인덱스를 다시 계산해서 고쳤습니다. `order` 유형도 7개 레슨의 Q7을
전환해서 4문제(1.4%)→11문제(3.9%)로 목표 비율에 맞췄습니다.

**오답 품질 개선**: "인터넷이 끊겨서" 같은 상식으로 걸러지는 오답을, 개념을 알아야만
가려낼 수 있는 그럴듯한 오답으로 58개 파일 중 약 39개 파일에서 재작성했습니다.
상세는 `Daon-code_할일.md`의 "오답(distractor) 품질 개선" 항목 참고.

## 남은 판단 거리

지금 결론 낼 필요는 없지만 염두에 둘 것들입니다.

**리텐션 모델이 안 맞을 가능성**
듀오링고식 매일 접속 모델은 "매일 조금씩 쌓는" 학습에 최적화돼 있는데,
바이브코딩러는 **막혔을 때만 찾는** 성향이 강할 수 있어요.
출시 후 데이터를 보고 "막혔을 때 찾아오는 앱"으로 성격 조정이 필요할 수 있습니다.

**수익 모델**
하트(생명) 시스템은 안 씁니다. 대신 꾸미기 과금을 검토하는데,
꾸미기는 남에게 보여질 때 지갑이 열리므로 리그·프로필 공개가 전제조건이에요.
에셋은 AI 생성으로 시작 → 반응 확인 → 외주 순서.
테마는 색상 값만 바꾸면 되어 그림이 불필요하므로 1차 수익 아이템으로 적합합니다.

**콘텐츠가 곧 제품**
앱 구조는 어느 학습 앱이나 비슷해요. 차별화는 전적으로 콘텐츠에서 나오므로,
406문제의 질이 성패를 가릅니다. 개발보다 콘텐츠 제작에 시간이 더 들 것으로 봐야 해요.
