## 핵심 결정 요약

한눈에 보는 확정 사항입니다. 자세한 근거는 기획서를 참고하세요.

### 제품

```
타깃      바이브코딩으로 뭔가 만들지만 코드는 모르는 사람
컨셉      문법을 외워 "직접 짜기"가 아니라, AI가 준 코드를 "이해하기"
커리큘럼   지식 분류 순서가 아닌, 프로젝트 실제 여정 순서 (12단계 58레슨, 9~12단계는 확장 추가)
문맥      JavaScript + React (주요 바이브코딩 툴이 생성하는 스택)
```

### 기술

```
앱        React Native + Expo
백엔드     Supabase (유저 데이터만)
콘텐츠     로컬 JSON — Supabase에 콘텐츠 테이블 두지 않음
채점      Edge Function이 서버에서 확정, 클라이언트 계산은 신뢰하지 않음
보안      RLS로 progress/daily_xp/XP 컬럼 클라이언트 쓰기 차단
갱신      EAS Update로 스토어 심사 없이 콘텐츠 반영
```

### 게임화

```
EXP       레슨 완료 10 + 만점 보너스 5 + 하루목표 20 (재도전은 0 — 파밍 방지)
코인      공부해서 버는 화폐 — 코인 펫(91마리, 종별 40~100코인) 구매
프리즘     유료 재화(한도 없음) — 팀 펫이 시간마다 채굴 + 현금 결제(연결 전).
          스트릭 지키기·프리즘 펫(22마리) 구매·코인 교환에 쓴다
펫       113마리, 최대 8마리를 "팀"으로 꾸려 광산·방에 내보냄 (상점에서 구매)
게스트     정상 EXP·코인의 80%, 로그인 시 차액을 보너스로 환급
스트릭     Asia/Seoul 고정, 하루 빠지면 자동 보호 없이 프리즘으로 직접 선택해 지킴
로그인     배치고사 본 사람 → 결과 확인 시점에 강제
          안 본 사람 → 1단계(5레슨) 완료 시점에 강제
```

수치와 정한 이유는 **[재화_경제.md](재화_경제.md)**가 기준입니다.

## 남은 판단 거리

지금 결론 낼 필요는 없지만 염두에 둘 것들입니다.

**리텐션 모델이 안 맞을 가능성**
듀오링고식 매일 접속 모델은 "매일 조금씩 쌓는" 학습에 최적화돼 있는데,
바이브코딩러는 **막혔을 때만 찾는** 성향이 강할 수 있어요.
출시 후 데이터를 보고 "막혔을 때 찾아오는 앱"으로 성격 조정이 필요할 수 있습니다.

**수익 모델 (결정됨 → 진행 중)**
하트(생명) 시스템은 쓰지 않기로 한 원래 방향 그대로입니다. 꾸미기 대신 **펫 채굴·구매
재화(프리즘)**를 현금화 지점으로 잡았고, 상점 UI와 가격표는 이미 있습니다(`재화_경제.md`).
남은 건 실제 결제 연동(구글 플레이 콘솔 → 인앱 상품 → 결제 라이브러리 → 영수증 검증) —
`Daon-code_할일.md`의 "프리즘 현금 결제 연결" 항목 참고.

**콘텐츠가 곧 제품**
앱 구조는 어느 학습 앱이나 비슷해요. 차별화는 전적으로 콘텐츠에서 나오므로,
문제의 질이 성패를 가립니다. 지금은 13개 트랙 1,650문제+ 규모로, 자격증 트랙(SQLD 등)은
사용자가 실제 응시 전 한 번 더 검수하는 걸 권장합니다(상세는 `archive/기능_로드맵.md`).
