# 추가 아이디어 (2026-09-28)

`기능_로드맵.md`에 이미 있는 것(오답노트, 트랙, 캐릭터/펫 등)과 겹치지 않는 것만 모았다.
확정된 계획이 아니라 검토용 후보다.

---

## 1. 보상 구조 개편 — EXP + 코인 + 프리즈 (듀오링고 방식) ⭐ 결정

### 지금 구조와 문제

- XP는 레벨을 올리는 용도 하나뿐이고, 모아서 쓸 곳이 없다.
- 스트릭 프리즈는 기획서 7번에 "7일마다 1개 지급"이라고 돼 있다.
  그런데 코드에는 **소모만 있고 지급하는 곳이 없어서**, 지금 모든 사용자의 프리즈가 0개다.

### 바꿀 구조

```
문제 풀기 ──▶ EXP  (레벨·진행바용, 지금의 XP. 쓰지 않고 쌓이기만 한다)
         └─▶ 코인 (화폐, 모아서 쓴다)

코인 ──▶ 스트릭 프리즈 / 캐릭터 / 테마 구매

프리즈 ──▶ 스트릭 보호 전용 (하루 빠지면 자동 소모)
```

| | 듀오링고 | 이 앱 |
|---|---|---|
| 레벨/진행용 | XP | EXP |
| 화폐 | 보석 💎 | 코인 (이름 미정 — 예: `req`, 크레딧) |
| 화폐 얻는 법 | 레슨, 퀘스트 | 레슨 완료, 전부 정답, 하루 목표 |
| 화폐 쓰는 곳 | 스트릭 프리즈, 꾸미기 | 스트릭 프리즈, 캐릭터, 테마 |
| 프리즈 | 상점에서 사서 보유, 빠진 날 자동 사용 | 같음 |

### 이렇게 정한 이유 (검토한 대안)

- **"XP를 없애고 시간이 지나면 EXP가 차는 방치형"** → 기각.
  공부 안 해도 레벨이 오르면 레벨이 의미를 잃는다.
- **"프리즈를 화폐로 써서 캐릭터 구매"** → 기각.
  프리즈는 스트릭 보험이라, 화폐로도 쓰면 "캐릭터 vs 보험" 사이에서 고민하게 된다.
  캐릭터를 사면 스트릭이 끊겨 이탈하고, 보험으로 아끼면 상점을 아무도 안 쓴다.
  한 자원이 두 역할을 하면 둘 다 제대로 안 된다.
- **"문제를 풀 때 프리즈(비용) 소모"** → 기각. 핵심 행동인 공부에 비용을 붙이면 안 된다.
- **듀오링고와 다르게 갈 부분**: 하트(목숨) 제도는 두지 않는다. 틀려도 계속 풀 수 있어야 한다.

### 수치 (초안)

| 행동 | EXP | 코인 |
|---|---|---|
| 레슨 최초 완료 | +10 (지금과 같음) | +5 |
| 전부 정답 | +5 (지금과 같음) | +3 |
| 하루 목표 달성 | +20 (지금과 같음) | +10 |
| 이미 완료한 레슨 재도전 | 0 | 0 (파밍 방지 원칙 유지) |

| 상품 | 가격 | 제한 |
|---|---|---|
| 스트릭 프리즈 | 50 코인 | 최대 2개 보유 (기획서 7번) |
| 테마 | 30~100 코인 | 기본 테마 1~2개는 무료로 남긴다 |
| 캐릭터 | 미정 | 캐릭터 기능(로드맵 5번)이 생긴 뒤 |

- 게스트 80% 규칙은 코인에도 똑같이 적용하고, 계정을 연결하면 EXP처럼 코인도 환급한다.
- 수치는 레슨 하루 2~3개 기준으로 **1주일에 프리즈 1개**를 살 수 있게 맞춘 것이다.
  기획서의 "7일마다 1개"와 비슷한 속도다.

### 구현 메모

- `profiles`에 `coins` 컬럼을 추가한다. XP 컬럼처럼 가드 트리거로 클라이언트 쓰기를 막는다.
- 코인 계산은 `scoring.ts`에 순수 함수로 추가한다. 저장은 기존 `apply_lesson_result`에 코인 증가만 붙인다.
- 구매는 Edge Function `purchase`가 한다.
  - 한 트랜잭션에서 잔액 확인 → 차감 → 지급
  - 동시 구매로 잔액이 음수가 되지 않게 한다.
- 이미 푼 레슨을 코인으로 소급 지급할지는 따로 정한다.
  (예: 오픈 기념으로 완료 레슨 수 × 5를 한 번 지급)

### 만드는 순서

1. **코인 지급** — 제출 시 코인 적립, 상단바에 코인 표시
2. **프리즈 구매** — 상점 화면에 상품 1개만
3. **테마 잠금 + 구매** — 이미 있는 테마 10종에 가격 붙이기 (`할일.md`의 `free` 필드 항목)
4. **캐릭터** — 로드맵 5번 캐릭터/펫 기능이 생기면 상점에 추가

## 2. 방치형 — "내 서버실" (보류, 1번 이후 선택 사항)

1번 코인이 생긴 뒤, 코인을 얻는 **추가 경로**로 붙일 수 있다.
방치로는 **EXP를 주지 않고 코인만** 쌓인다.

```
$ uptime 3h12m · load ▓▓▓▓░░ · 12 coin 대기중   [수거]
```

- 생산 속도 = 완료한 레슨 수에 비례 (공부할수록 빨라짐), 스트릭이 길면 배수
- 오프라인 누적 상한 12시간 — 하루 1~2번 들어오게
- 하루 쉬면 🐛 버그가 생겨 생산이 줄고, **오답노트·복습 1문제를 풀어야** 없어진다
  → 방치가 복습하러 들어오는 이유가 된다 (안 쓰는 `user_term_review` 활용 기회)
- 수거는 서버 시각 기준으로 계산한다 (기기 시계 조작 방지)
- 1번 상점이 실제로 쓰이는지 본 다음에 결정한다

## 3. 그 밖의 아이디어 (쉬운 것 → 큰 것 순)

### 3-1. 학습 잔디 (GitHub contribution graph)
- 날짜별 XP가 `daily_xp`에 이미 쌓이고 있어서 **데이터 작업이 없다**.
- 개발자 감성에 맞고 구현이 가장 쉽다. 프로필 화면 또는 상단바 설명 패널에 넣는다.

### 3-2. 레벨업·보상 연출
- 레슨 완료 화면에 터미널 로그처럼 한 줄씩 찍는다.
  ```
  > +15 EXP  +8 coin
  > LEVEL UP  LV12 → LV13
  > streak 7d ✔
  ```
- 지금은 레벨이 올라도 상단바 숫자만 조용히 바뀐다.

### 3-3. 스트릭 위험 알림
- 밤 9시에 "오늘 1레슨만 풀면 7일 스트릭 유지"라고 알린다. 프리즈가 있으면 "프리즈 1개가 지켜줘요"라고 알린다.
- 알림 발송 스케줄러(할일 Phase 6)를 만들 때 같이 넣는다.

### 3-4. 용어 복습 (라이트너 박스)
- 기획서 8번에 설계돼 있고 테이블(`user_term_review`)도 있지만, 코드에서는 안 쓰고 있다.
- 복습하면 코인을 조금 주면 쓸 이유가 생긴다.

### 3-5. 약점 레슨 추천
- 오답이 많이 쌓인 레슨을 홈에서 "다시 풀어볼까요?"로 제안한다. `wrong_answers`를 레슨별로 세면 된다.

### 3-6. 단계 완료 공유 카드
- 한 단계를 끝내면 터미널 스타일 이미지 카드("✔ 2단계 · 받은 코드, 뭐가 뭔지 — 완료")를 만든다.
- 인스타·카톡으로 공유할 수 있게 한다. 자연스러운 홍보 수단이다.

### 3-7. 주간 리포트
- 월요일에 지난주 요약을 보여 준다: 푼 레슨, EXP, 가장 많이 틀린 개념
- 알림 스케줄러가 생긴 뒤에 붙인다.

4. 상점 반응을 보고 **2번 방치형**, 캐릭터
